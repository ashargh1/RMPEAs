Note: This document describes the complete pipeline for generating data, training the model, and reproducing the figures in the manuscript. The framework includes the following 
eight components:

component 1. Sample Generation
SampleGeneration.ipynb generates the training samples in two part:
Part A) It generates Samples.txt, containing 70,000 RMPEA samples at T = 850 K.
Part B) It expands each composition to 6 temperature points, resulting in Samples_T.txt with 420,000 total samples and generates Samples_T.txt.
Note: Each line in both files correspond to the compoistion of one smaple where the format of each line is [Ti,Fe,Al,V,Ni,Nb,Zr,Mn,Co,Temp,Press]


component 2. Phase Labeling
PhaseLabeling.ipynb assigns phase labels using Thermo-Calc. The input file is Samples_T.txt or Samples.txt while it generates Phases_T.txt or Phases.txt, where the format of each line is 
[id,Ti,Fe,Al,V,Ni,Nb,Zr,Mn,Co,Temp,Press,FCC,BCC,HCP,B2,Laves,Sigma,Heusler,Liquid]


component 3. Feature Labeling
FeatureLabeling.ipynb generates the 51 input features for each sample in two part.
Part A) It uses Samples.txt, which is based on merging Samples_T.txt + Samples.txt from the earlier component, and Phi.txt as the main input files and generates labels.txt (primary features) as the output.
Part B) It uses labels.txt as the main input file and generates labels_extra.txt, which includes all 51 features (primary + secondary).
Note_1: Phi.txt must be generated by running the publicly available ASAP code using systems.txt, where each line defines a composition in the format of Ti0.35Fe0.10V0.35Zr0.20
Note_2: The format of both Label text files is [id,Ti,Fe,Al,V,Ni,Nb,Zr,Mn,Co,Temp,Press,Feat1,....Feat51]


component 4. Feature Engineering
FeatureEngineering.ipynb performs a two-stage feature engineering process. In the first stage (i.e., data cleaning):
Part A) It performs initial screening.
Part B) It removes samples that make the distribution less uniform. You need to run this part multiple times until you stop seeing the message: "Number of deleted RMPEAs = ...".
Part C) It compiles the cleaned dataset.
In the second stage (i.e., feature reduction):
Part A) It identifies highly correlated features to be removed.
Part B) It drops the selected features and generates the final training/test sets: xlo_1.npy, ylo.npy, xlo_test1.npy, ylo_test.npy
Note: For consistency in later steps, we rename: xlo_1.npy to xlo.npy and xlo_test1.npy to xlo_test.npy


component 5. Oversampling
Oversampling.ipynb applies our custom oversampling strategy to the dataset. The "phs" parameter controls which phase is oversampled. The notebook uses xlo_1.npy 
and ylo.npy from the previous component as inputs and produces the oversampled training data (xlo_oversampling.npy, ylo_oversampling.npy) along with the 
validation sets (xlo_val.npy, ylo_val.npy)


component 6. Model training
Initially, you need to do hyperparameter tuning through Bayesian optimization. For that, you need to first execute MDN_Finetuning.ipynb to select the best model architecture. The 
output of this code is BO_Restuls.txt wherein each line correponds to the architecture of the model and the format of each line is [dropout,dropout_rate,batch_normalization,batch_size,layers,neurons,learning_rate,number_of_Gaussians,validation loss]
You need to choose the architecture based on the value of the final collumn. Next, you need to train the final MDN model using the optimized architecture from the earlier stage via 
MDN.ipynb on xlo_oversampling.npy, ylo_oversampling.npy, xlo_val.npy, ylo_val.npy, xlo_test.npy, and ylo_test.npy. The selected training epoch corresponds to 
the minimum value in the final column of res.npy, which is used as the criteria for identifying a well-trained model.


component 7. Performance evaluation
PerformanceEvaluation.ipynb generates Figure 1, Figure 3-7 of the manuscript.
Note that the final checkpoint for all six MDN is uploaded in "checkpoint" folder. The checkpoint folder also contains the final model checkpoints for the BCC-phase
ablation and ensemble studies. The naming convention specifies the number of features used in training. For instance, "model-850_bcc_16feat" represents the checkpoint of a model 
trained with the top 16 features. All parameters or parts that users may need to modify, depending on their specific goal, are highlighted with a hashtag (#)


component 8. Active learning
ActiveLearning.ipynb contains the code for the active learning process including the one needed to prepare the training dataset. In addition, it plots Figure 8-10 
of the manuscipt. All parameters or parts that users may need to modify, depending on their specific goal, are highlighted with a hashtag (#). Also, further 
explanation at specific parts that might be challenging to follow are provided. Note that all the final checkpoints for both high-certain and low-certain routes and 
for different samples size are provided in "checkpoint" folder. In addition, as an example, the codes for conducting cycle 4 of the high-certain route with 500
samples are provide in "Training_highcert_500_cycle4" folder.
